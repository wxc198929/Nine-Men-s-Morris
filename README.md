## 墙壁围棋 WallGo

游戏入口：`https://wxc198929.github.io/Nine-Men-s-Morris/game/wall-go/`。九子棋页与墙壁围棋页可以相互切换，共用注册与登录账号；房间和积分分别保存。

墙壁围棋的双人基础玩法参考 [WallZero 论文 §2.1](https://arxiv.org/html/2606.17847#S2)，本站采用定制规则：7×7 格，每方四子，每回合必须移动 **1–2 步，不得原地筑墙或回到起点**；允许拐弯，不得越子，移动后必须在终点边上筑墙。双人红方 B2/F6、蓝方 B6/F2 预置，按红蓝蓝红补齐各四枚。

可选择双人或三人人机、同屏对战、好友联机。三人使用红、蓝、绿三方，空盘按红蓝绿、绿蓝红、红蓝绿、绿蓝红顺序布齐十二子，之后红蓝绿轮流行动；人机中玩家执红，另两方由电脑操作。联机按所选人数创建房间，满员后开始。

三人局每人有一次破墙机会。选棋后点击“使用破墙”，选择待破的墙，再选择跨墙终点：总路程仍为1–2步，必须在第一或第二步实际跨过该墙，不能跨第二道墙或越子；终点仍须筑墙，可重新筑回刚跨过的边。破墙、移动和筑墙一起提交后才扣机会，取消或重选不扣。双人没有破墙。旧规则本地棋局保留在旧存储中，新规则从新局开始，使用 `wall-go-v2` 保存。

区域内仅有一种颜色时整区归该方，空区中立，混色区待定。全部颜色分隔后按总地盘、最大单块区域依次比较，仍同则并列；无合法完整回合的玩家自动跳过，全部无法行动时按当前地盘结算。三人联机一方认输移除其棋子，其他方继续，整局结束统一结算。并列第一者记和，其他方记负；使用各方赛前积分做两两 Elo、K=32/(人数−1)，每一对的积分变化相反，总积分守恒。双人与三人共用墙壁围棋排行榜，独立于九子棋。

支持三级难度、合法走法/破墙/筑墙提示、确定地盘着色、本地悔棋和自动续局。AI 在 Worker 中运行；高手约1.8秒预算，双人用最多六层 Alpha-Beta，三人用最多四层 Max-n，每方分别优化自己的得分，深层筛选候选走法，因此不保证全局最优。同分走法会随机变化。

前端在 `dist/game/wall-go/`，权威引擎副本在 `supabase/functions/wallgo-api/engine.js`。修改规则时同步两份，测试会校验一致性。`supabase/wallgo-schema.sql` 记录初始迁移 `wallgo_online`，`supabase/wallgo-multiplayer.sql` 记录已部署的 `wallgo_three_players` 扩展（人数、第三位玩家和逐方积分变化）。`wallgo_profiles` 与 `wallgo_rooms` 独立于九子棋数据，启用 RLS 与仅服务端写入权限；所有非排行榜请求通过 Auth 校验，后台权威验证移动和破墙额度。

本地启动后访问 `http://127.0.0.1:4173/game/wall-go/`；`node --test` 同时验证两款游戏。

上线校验：58项规则、权限和真实 Worker 测试通过；三人随机完整棋局、破墙跨越、一次额度、禁止原地、跳过受困玩家、绿方计分及部分并列均覆盖。浏览器验证完整移动破墙筑墙、取消预览、刷新恢复；数据库事务验证满员开局、绿方成员权限、版本冲突、重复结算保护、三方 Elo 和双人兼容，全部临时行随事务回滚。此前双人版本还做过真实临时双账号完整联机测试。项目级 Auth 仍有原有“泄露密码检测未启用”提示，参见 [Supabase 密码保护说明](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection)。

适配手机和电脑的九子棋小游戏，支持人机对战、同屏双人、好友联机、游戏账号和积分排行榜。人机与同屏模式可独立运行；联机和账号使用 Supabase 后台。

## 本项目规则

- 三重方框，共 24 个落点；无斜线，中心不可落子。
- 每方九子，白方先行，交替布子。
- 同色三子占满一条完整连线，可吃对方一子。优先吃未成三的棋子；若对方全部成三，则可吃其中任意一子。
- 同一手形成两条线也只吃一子；拆开后重新成三可再次吃子。
- 双方布子结束后，每回合沿线移到相邻空点，不能跳子。
- **三子不能飞：即使仅剩三子，也只能沿线移动一步。**
- 布子结束后，不足三子或轮到行棋时无棋可走者负。
- 相同棋盘、相同待落子数和相同行棋方出现三次，判和。

人机模式下玩家执白。悔棋会撤回到玩家上次完整操作前；双人模式每次撤回一步操作（吃子也算一步操作）。刷新页面可继续当前浏览器中的对局。

## 本地运行

安装 Node.js 22 或更高版本后：

```sh
npm start
```

在浏览器打开 `http://127.0.0.1:4173/game/`。请使用本地服务器，直接双击 HTML 文件可能无法加载模块和电脑对手。

运行规则检查：

```sh
npm test
```

## GitHub Pages

在仓库的 **Settings → Pages → Build and deployment → Source** 选择 **GitHub Actions**。工作流会先运行规则测试，再发布 `dist/` 下的静态文件。每次推送到 `main` 自动更新。

首次开启 Pages 后，如果先前的工作流已失败，到 **Actions → Test and deploy game** 重新运行，或推送新的提交。

网页使用相对路径，支持仓库子路径部署。人机和同屏对局保存在浏览器本地；注册时邮箱、密码交由 Supabase Auth 管理，联机棋局、昵称与战绩保存在后台。排行榜不公开邮箱。

## 人机难度

- **高手挑战**：迭代加深的 Alpha-Beta 搜索，最多 12 层完整走法（每层包含成三后的吃子），每手约 1.8 秒的计算预算。评估子力、可形成的连线、多个成三威胁、活动空间和被封锁棋子；在搜索边界继续检查直接吃子。包含置换缓存、走法排序和三次重复局面处理。
- **认真下棋**：原有的两层攻防搜索，落子较快。
- **轻松入门**：优先考虑局部好棋，偶尔选择次优走法。

新玩家默认选择“高手挑战”；已有玩家保留之前的难度选择，可直接在“电脑难度”中切换，无需重新开局。高难度在 Web Worker 中计算，不阻塞棋盘操作；思考期间仍可悔棋、切换难度或重新开局。设备速度会影响实际搜索深度，因此不保证每手都达到 12 层，也不保证最优解。浏览器不支持 Worker 时使用快速的普通难度作为备用。

“高手挑战”会在搜索评分相同的走法之间随机选择；开局还会在保持当前局面不变的对称走法之间变化。浏览器会记住最近 128 个局面中电脑上次的完整走法，有同等评分或对称的其他选择时，优先避免重复。变化不会故意放弃搜索中评分更高的走法，因此必须防守或只有一个最佳选择时，仍可能走相同的棋。对局与走法记忆都只保存在当前浏览器。

## 联机、游戏账号与排行榜

网页保留 GitHub Pages 部署，账号、房间与战绩使用 Supabase 项目 `nine-mens-morris`（`ttgbyjjdviivmkgtxuxw`）。玩家在游戏网页使用邮箱、密码和昵称注册，无需拥有 Supabase、GitHub 或 Google 账号。

- 点击“好友联机”，登录后创建房间，将六位房间码发给好友；房主执白，加入者执黑。
- 正在进行的对局保存在后台；登录后进入“好友联机”可恢复，断线重连后继续。
- 切换到人机或同屏模式不会结束联机房间。可通过“认输”结束联机对局；等待中的房间可取消，等待超过一天不可再加入。
- 联机不支持悔棋。后台独立验证走法、轮次和房间成员，并用版本号防止并发重复落子。
- 仅已结束的真人联机对局计入排行榜；初始积分 1200，Elo K=32。认输也计入战绩。排行显示昵称、积分、胜负和局，不公开邮箱。
- 当前采用注册后立即登录，不验证邮箱归属；自定义发信服务尚未配置，页面暂不提供邮件找回密码。请妥善保存密码。

## 后台维护

`supabase/schema.sql` 记录已部署的数据库定义（托管迁移 `morris_online`、`explicit_server_only_policies`）。所有数据表启用 RLS，普通用户无直接读写权限；仅 Edge Function 内部的服务身份可调用写入函数。浏览器配置 `dist/game/shared/online-config.js` 只有公开项目地址与 publishable key，不能放入 service-role 密钥。

`supabase/functions/morris-api/index.ts` 使用固定版本 `@supabase/supabase-js@2.119.1`，浏览器使用同版本随附的 UMD 包及 MIT 许可证。排行榜匿名可读；其余请求均通过 `Auth.getUser` 验证用户，房间与积分更新在数据库事务中完成。`verify_jwt=false` 仅为匿名排行提供入口，不能移除处理器中的身份校验。

游戏引擎同时保存在 `dist/game/nine-mens-morris/engine.js` 与 `supabase/functions/morris-api/engine.js`，修改后必须同步；测试会比较两者一致性。前端每 2.5 秒同步棋局，重复局面三次判和、三子不能飞等规则与本地模式相同。

若重新部署项目：启用 Email provider；保持 Confirm email 关闭以匹配当前注册方式。若以后启用邮件验证或找回密码，先配置 SMTP、生产 Site URL 与允许跳转地址，再开放对应网页入口。生产地址为 `https://wxc198929.github.io/Nine-Men-s-Morris/`。
